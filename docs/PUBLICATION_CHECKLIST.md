# Publication checklist

Before making this repository public:

- [ ] obtain project-owner permission to publish the implementation, derived contract, schema fragments, product name, and fixture terminology;
- [ ] choose and approve a license, then add its exact text;
- [ ] verify history contains no secrets, production data, tokens, internal URLs, screenshots, or deployment evidence;
- [ ] compare `api/openapi.yaml` against the authoritative Flutter checkout;
- [ ] verify `api/SOURCE_PROVENANCE.md` hashes against the intended source revision;
- [ ] confirm all local fixture media URLs and identities are synthetic;
- [ ] run formatting, vet, build, unit/integration/contract/race tests, and Compose validation;
- [ ] keep `README.md` and `docs/STATUS.md` explicit that the candidate is not deployed unless that status truly changes;
- [ ] have the project owner review repository visibility and attribution.
